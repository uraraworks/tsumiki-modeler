## 技術構成（プロトタイプ段階）

| 項目 | 選択 | 理由 |
|---|---|---|
| 実装 | 素の HTML + ES Modules（ビルド不要） | GitHub Pages に置くだけで動く。試行のサイクルが最短 |
| Three.js | CDN (jsdelivr) を importmap で読む | npm/Vite 導入は必要になってから |
| 言語 | JavaScript（TS は後回し） | プロトタイプ段階で型定義に時間を使わない |

> いろはペイントは Vite + TS だが、こちらは「動きを見ながら進める」段階なので
> あえてビルド無しから始める。規模が育ったら Vite へ移行する（src/ をモジュール分割しておく）。

## 最初から守る設計ルール（企画メモ 15 節）

MCP 対応を後から無料で足せるようにするため、以下 2 点はプロトタイプ第一版から守る。

1. **単一 JSON ドキュメントが唯一の真実**
   - `ModelDoc`（parts / bones / textures …）が状態のすべて
   - Three.js のシーンはそこからの派生物。逆方向に状態を持たない
   - パーツは安定 ID ＋ 意味のある名前（`arm_l` など）を持つ
   - 座標・寸法は整数グリッド単位
2. **すべての編集はコマンド経由**
   - `add_box` / `set_transform` / `delete_part` …
   - Undo/Redo はコマンド履歴で実現し、そのまま MCP の API になる

## 決めたこと・ペンディング

- 拡大は必ず整数倍。端数はレターボックス（黒帯）で埋める（企画メモ 3 節の絶対ルール）
- テクスチャ関連の設定は P4 で入れる（NearestFilter / mipmap 無効 / SRGB）
- アウトラインは逆押し出しで開始。深度＋法線のエッジ検出は後で置き換え
- 公開先リポジトリ名は `tsumiki-modeler`（企画メモ 17 節）— まだ作成していない
